What this does and doesn't do

Scans

  • Every text file on the branch, plus lockfiles, binaries and large files in deep mode
  • Git history — a secret deleted in a later commit is flagged as still reachable
  • Private repos, with a token that has read access
  • Known credential formats, and unlabelled high-entropy strings

Limits worth knowing

  • History goes back a bounded number of commits, not to the first commit
  • GitHub omits the diff for very large commits; those files are re-read whole instead
  • Private repos cost one API request per file, so large ones eat an hourly budget fast
  • Compressed and media files are skipped even in deep mode — their bytes are unreadable noise

Findings are pattern matches, not confirmed leaks. Verify anything flagged before rotating a key, and expect false positives from entropy detection — it trades precision for not missing the unlabelled cases.

Discovery is complete; scanning is sampled

Enumerating new repos is cheap — every one is seen, in order, with no gaps. Scanning them is not: GitHub gets roughly 200,000 new public repos a day and one browser tab gets a few thousand API requests an hour. The dashboard therefore reports discovery and scan coverage as two separate numbers, because collapsing them into one would misrepresent what this actually sees.

Findings from other people's repositories are redacted here and never stored in the clear. If you act on one, report it to the repo owner or through GitHub's private vulnerability reporting — don't publish it.

Stopped
History scanning is off here by design — one API call per commit is too costly at this volume.
